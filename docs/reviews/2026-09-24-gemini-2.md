# Review 2: trading core (PR #16)

Reviewer: Gemini 3.8 Flash (High) via `agy`, read-only, with all files in the prompt. The reviewer's verdict before the fixes: "not safe to run in live mode". Every finding was checked by Claude before it was fixed; each fix has a regression test where one is possible.

| # | Sev. | Finding | Checked | Fix |
|---|---|---|---|---|
| 1 | P0 | The API error counter was reset by every successful read, so failing orders never reached the kill-switch threshold | Confirmed | Separate counter for order requests, reset only by a successful order request. Test. |
| 2 | P0 | A dry run marked the session as done, so the real run right after placed nothing | Confirmed | A dry run no longer marks the session. Test. |
| 3 | P0 | Paper: the candle already running when the order was placed was checked, so a dip before the order could stop it out | Confirmed | That candle is skipped. Test. |
| 4 | P1 | Position history was called with a wrong pagination parameter | Plausible; exact semantics unsure | Parameter removed: latest 100 records, filtered by time. |
| 5 | P1 | The live_small stage counted demo trades as live, so real money could skip the 0.25R phase | Confirmed | Only mode `live` counts. |
| 6 | P1 | Daily loss added open losses from earlier days, causing false daily stops | Confirmed | Loss limits now use equity changes between session snapshots. Test. |
| 7 | P1 | Free margin summed balances in different currencies | Confirmed | Only the USD balance (the X-Perps settlement currency). **Verify in demo.** |
| 8 | P1 | Limit entries were cancelled at the next session, ignoring the strategy's expiry | Confirmed | The expiry is stored and cancelled by the backtest's rule. |
| 9 | P1 | Beta was computed differently live and in the backtest | Confirmed | Live uses the backtest's function. |
| 10 | P1 | An aborted holdout run could be repeated | Confirmed | A started run already counts. Test. |
| 11 | P1 | Target exits were recorded as "other" because market fills land near, not at, the target | Confirmed | Nearest level decides; time exits are recognized. Test. |
| 12 | P2 | Re-running after a crash hit a duplicate key and crashed | Confirmed | An already-handled signal is skipped. |
| 13 | P2 | Contract size could be formatted as `12.300000000000002` | Confirmed (X-Perps lots are 1 today) | Exact decimal formatting. |
| 14 | P2 | An error cancelling already-removed stops crashed housekeeping | Plausible | Tolerated; housekeeping errors are reported per trade. |
| 15 | P2 | A withdrawal looked like a drawdown and triggered the kill switch | Confirmed | `--cashflow` records deposits and withdrawals; peak and loss limits exclude them. Test. |
| 16 | P2 | A second X-Perp for the same coin could overwrite the first | Not the case today (214 instruments, all USD, no duplicates) | USD only, never overwrite. |
| 17 | P2 | `--resume` could be piped in by a script or agent | Confirmed | **Partial:** only works from an interactive terminal. Not cryptographic; the server-side rule and the guard remain. |
| 18 | P3 | Margin check ignored the opening fee | Confirmed | 0.1% notional buffer. |

## What must be true before live mode

1. A demo session has placed, filled, stopped and closed a trade. Reconciliation, the journal and the report must match what OKX shows (findings 4, 7, 14 checked against the real API).
2. X-Perps fee tiers are known and in the cost model (SPEC 15).
3. A strategy has passed stage 3, the verifier review, the holdout (gatekeeper) and at least 3 months and 100 trades of paper trading (SPEC 6.4).
